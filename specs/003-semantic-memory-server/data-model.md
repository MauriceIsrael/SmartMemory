# Data Model: Semantic Memory MCP Server

**Feature**: 003-semantic-memory-server
**Date**: 2025-11-22
**Status**: Complete

## Overview

The Semantic Memory MCP Server operates on RDF triples as the fundamental data structure. This document describes the core entities, their relationships, and the custom vocabulary used to support provenance tracking and uncertainty handling.

## Core RDF Data Structures

### Triple

The atomic unit of knowledge in the system.

**Structure**:
```python
class Triple:
    subject: URIRef | BNode      # Entity or blank node
    predicate: URIRef             # Property from ontology
    object: URIRef | Literal      # Value or another entity
```

**Sources**:
- **Explicit**: User-provided via `add_memory` tool
- **Inferred (Level 1)**: Generated by OWL-RL reasoner from ontological axioms
- **Inferred (Level 2)**: Generated by SPARQL CONSTRUCT rules

**Storage**: `rdflib.Graph` in-memory, persisted to Turtle/SQLite/Oxigraph

### Provenance Record

Metadata tracking the origin and confidence of each triple.

**Vocabulary**: Custom namespace `http://example.org/semantic-memory/` (prefix: `sem:`)

**Properties**:
```turtle
PREFIX sem: <http://example.org/semantic-memory/>
PREFIX prov: <http://www.w3.org/ns/prov#>
PREFIX xsd: <http://www.w3.org/2001/XMLSchema#>

# Provenance properties
sem:source           # "user" | "owlrl" | "sparql-rule"
sem:sourceRule       # URI of SPARQL rule file (for Level 2 inferences)
sem:timestamp        # xsd:dateTime when triple was added
sem:confidence       # xsd:decimal (0.0-1.0) for uncertain inferences
sem:uncertain        # xsd:boolean - true if requires verification
sem:verificationId   # Unique ID for pending verification requests
sem:conflict         # Links to conflicting triples
```

**Example**:
```turtle
# Explicit triple
:alice schema:worksFor :TechCorp .

# Provenance for explicit triple
_:prov1 a sem:ProvenanceRecord ;
    sem:about [:alice schema:worksFor :TechCorp] ;
    sem:source "user" ;
    sem:timestamp "2025-11-22T10:30:00Z"^^xsd:dateTime .

# Inferred triple with provenance
:alice schema:colleague :bob .

_:prov2 a sem:ProvenanceRecord ;
    sem:about [:alice schema:colleague :bob] ;
    sem:source "sparql-rule" ;
    sem:sourceRule <file:///src/rules/defaults/coworkers_inference.rq> ;
    sem:timestamp "2025-11-22T10:30:01Z"^^xsd:dateTime ;
    sem:confidence "1.0"^^xsd:decimal .
```

## Ontology Entities

### Loaded Ontologies

Standard vocabularies loaded at startup:

#### FOAF (Friend of a Friend)
**Namespace**: `http://xmlns.com/foaf/0.1/` (prefix: `foaf:`)

**Key Classes**:
- `foaf:Person` - Individual human
- `foaf:Agent` - Any actor (person, org, software)
- `foaf:Organization` - Group or company
- `foaf:Document` - Information resource

**Key Properties**:
- `foaf:knows` - Social relationship
- `foaf:name` - Name of entity
- `foaf:member` - Membership in group
- `foaf:homepage` - Web page

#### Schema.org
**Namespace**: `https://schema.org/` (prefix: `schema:`)

**Key Classes**:
- `schema:Person`
- `schema:Organization`
- `schema:Place`
- `schema:Event`
- `schema:CreativeWork`

**Key Properties**:
- `schema:worksFor` - Employment relationship
- `schema:location` - Geographic location
- `schema:containedInPlace` - Spatial containment
- `schema:colleague` - Professional relationship
- `schema:interestOf` - Topic interest
- `schema:about` - Subject matter

#### RDFS (RDF Schema)
**Namespace**: `http://www.w3.org/2000/01/rdf-schema#` (prefix: `rdfs:`)

**Key Properties**:
- `rdfs:subClassOf` - Class hierarchy
- `rdfs:subPropertyOf` - Property hierarchy
- `rdfs:label` - Human-readable label
- `rdfs:comment` - Description

#### SKOS (Simple Knowledge Organization System)
**Namespace**: `http://www.w3.org/2004/02/skos/core#` (prefix: `skos:`)

**Key Classes**:
- `skos:Concept` - Abstract idea or topic
- `skos:ConceptScheme` - Taxonomy or classification

**Key Properties**:
- `skos:broader` - Hierarchical relationship
- `skos:narrower` - Inverse of broader
- `skos:related` - Associative relationship

### Ontology Cache Metadata

**Structure**:
```python
class OntologyCacheMetadata:
    url: str                      # Remote ontology URL
    local_path: Path              # Cache file path
    etag: str | None              # HTTP ETag header
    last_modified: str | None     # HTTP Last-Modified header
    cached_at: datetime           # When cached locally
    format: str                   # "rdf/xml" | "turtle" | "n3"
```

**Storage**: `.cache/ontologies/*.meta.json` alongside cached `.rdf` files

## Inference Rules

### Rule Definition

**Structure**:
```python
class InferenceRule:
    id: str                       # Filename without extension
    file_path: Path               # Absolute path to .rq file
    sparql_query: str             # CONSTRUCT query text
    source: str                   # "default" | "custom"
    description: str | None       # Extracted from # comment in first line
    is_active: bool               # False if validation failed
    validation_error: str | None  # Error message if invalid
    execution_count: int          # Number of times executed
    triples_generated: int        # Total triples created by this rule
```

**Metadata Extraction**:
- First line comment becomes description: `# This rule infers X from Y`
- If no comment, description is None

**Example Rule File** (`spatial_transitivity.rq`):
```sparql
# Infers transitive containment relationships (if A in B and B in C, then A in C)
PREFIX schema: <https://schema.org/>

CONSTRUCT {
    ?inner schema:containedInPlace ?outer .
}
WHERE {
    ?inner schema:containedInPlace ?middle .
    ?middle schema:containedInPlace ?outer .
    FILTER NOT EXISTS { ?inner schema:containedInPlace ?outer }
}
```

## Verification Requests

### Uncertain Inference

Temporary structure for inferences awaiting user confirmation.

**Structure**:
```python
class VerificationRequest:
    id: str                       # UUID for identification
    triple: Triple                # The uncertain inference
    confidence: float             # 0.0-1.0 (from rule)
    source_rule: str              # Rule that generated it
    context: dict                 # Supporting facts that triggered the rule
    created_at: datetime
    status: str                   # "pending" | "confirmed" | "rejected"
```

**Storage**: Separate "pending verifications" graph, not merged into main graph until confirmed

**Example**:
```python
verification_request = {
    "id": "ver_abc123",
    "triple": {
        "subject": "http://example.org/alice",
        "predicate": "http://xmlns.com/foaf/0.1/knows",
        "object": "http://example.org/bob"
    },
    "confidence": 0.6,
    "source_rule": "coworkers_inference.rq",
    "context": {
        "evidence": [
            {"s": "alice", "p": "worksFor", "o": "TechCorp"},
            {"s": "bob", "p": "worksFor", "o": "TechCorp"}
        ]
    },
    "created_at": "2025-11-22T10:30:00Z",
    "status": "pending"
}
```

## Conflict Detection

### Conflict Record

Represents detected inconsistencies in the knowledge graph.

**Structure**:
```python
class Conflict:
    id: str                       # Unique identifier
    type: str                     # "contradictory_literal" | "disjoint_class" | "functional_property"
    triples: list[Triple]         # Conflicting assertions
    provenance: list[ProvenanceRecord]  # Origins of each triple
    detected_at: datetime
    resolved: bool                # True if user has resolved manually
```

**RDF Representation**:
```turtle
_:conflict1 a sem:Conflict ;
    sem:conflictType "contradictory_literal" ;
    sem:conflictingTriple [:alice :age "25"^^xsd:int] ;
    sem:conflictingTriple [:alice :age "30"^^xsd:int] ;
    sem:detectedAt "2025-11-22T10:35:00Z"^^xsd:dateTime ;
    sem:resolved false .
```

## Persistence Format

### Turtle Serialization (Default)

**File**: `knowledge_graph.ttl`

**Structure**:
```turtle
@prefix rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#> .
@prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .
@prefix foaf: <http://xmlns.com/foaf/0.1/> .
@prefix schema: <https://schema.org/> .
@prefix sem: <http://example.org/semantic-memory/> .

# Named graphs for organization
<http://example.org/graphs/explicit> {
    # User-provided triples
    :alice a schema:Person ;
        schema:worksFor :TechCorp .
}

<http://example.org/graphs/inferred> {
    # System-generated triples
    :alice a foaf:Agent .  # From OWL-RL
    :alice schema:colleague :bob .  # From SPARQL rule
}

<http://example.org/graphs/provenance> {
    # Metadata
    _:prov1 a sem:ProvenanceRecord ;
        sem:about [:alice schema:worksFor :TechCorp] ;
        sem:source "user" .
}
```

**Tables**:

## Validation Rules

### Triple Validation
1. **Subject**: Must be URIRef or BNode (not Literal)
2. **Predicate**: Must be URIRef from loaded ontologies (warn if custom)
3. **Object**: Can be URIRef, BNode, or Literal

### Provenance Validation
1. Every triple MUST have associated provenance record
2. `sem:source` MUST be one of: "user", "owlrl", "sparql-rule"
3. If source is "sparql-rule", `sem:sourceRule` MUST be present
4. `sem:confidence` MUST be between 0.0 and 1.0

### Rule Validation
1. SPARQL query MUST be valid CONSTRUCT query
2. MUST NOT use DELETE or UPDATE (read-only inference)
3. SHOULD include `FILTER NOT EXISTS` to prevent duplicate inferences
4. PREFIX declarations MUST match loaded ontologies

## Summary

The data model is organized around:
1. **RDF Triples**: Core knowledge representation
2. **Provenance**: Every triple tracked to source
3. **Ontologies**: Standard vocabularies define valid predicates
4. **Rules**: Declarative SPARQL for custom inference
5. **Verification**: Uncertain inferences held for user confirmation
6. **Conflicts**: Detected inconsistencies preserved with metadata

All entities are RDF-native and follow W3C standards, ensuring portability and standards compliance per the constitution.
