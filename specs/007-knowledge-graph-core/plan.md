# Implementation Plan: 007-knowledge-graph-core

**Feature Spec**: [spec.md](./spec.md)  
**Branch**: `007-knowledge-graph-core`

## 1. Technical Context

This feature defines the foundational data structures and mechanisms for the Smart Memory MCP server, particularly focusing on fact ingestion, processing, and a working memory model.

-   **Fact Structure**: The core `Fact` will be implemented as an immutable Pydantic v2 model in Python. Its unique `id` will be generated by hashing a canonical string representation of its subject-predicate-object triplet.
-   **Ingestion Queue**: An in-memory queue, `MemoryFactQueue`, will implement the `IFactQueue` abstract interface. It will utilize Python's `asyncio.Queue` for asynchronous operations and an `asyncio.Lock` to protect a `set` for efficient duplicate prevention within the queue.
-   **Fact Dispatcher**: The `FactDispatcher` will run as an `asyncio` coroutine, continuously monitoring the `IFactQueue`. It will dequeue facts in batches and distribute them to registered `IFactHandler` implementations. `asyncio.gather` will be used to execute multiple handlers concurrently.
-   **Fact Handlers**: The system will define an `IFactHandler` abstract interface, with concrete stub implementations for `FastInferenceHandler` and `DeepReasoningHandler` to demonstrate extensibility.
-   **Working Memory Graph (`AttentionGraph`)**: This will manage `MemoryNode` objects, which wrap `Fact`s or `Rule`s (a placeholder for now) and track their `activation_level` and `last_accessed` timestamp. It will use a Python dictionary for efficient storage and retrieval of `MemoryNode`s. Methods for `stimulate`, `decay`, `prune`, and `get_active_subgraph` will be implemented.
-   **Technologies**: Python 3.11+, Pydantic, `asyncio`, `hashlib`, `datetime`, `abc` module.

## 3. Phase 0: Outline & Research

The research phase focused on confirming best practices for the Python constructs specified in the feature description, as there were no explicit `[NEEDS CLARIFICATION]` markers.

-   **Artifact**: [research.md](./research.md)
-   **Summary**:
    -   Pydantic v2's `ConfigDict(frozen=True)` is ideal for immutable `Fact` models, with canonical serialization for `id` generation.
    -   `asyncio.Queue` combined with an `asyncio.Lock`-protected `set` is the recommended pattern for an async-safe, duplicate-preventing ingestion queue.
    -   `asyncio.gather` is the idiomatic approach for parallel execution of `IFactHandler`s within the `FactDispatcher`.
    -   A Python `dict` provides an efficient data structure for the `AttentionGraph` to manage `MemoryNode`s.

**Result**: All technical assumptions validated and implementation patterns confirmed. Ready for Phase 1.

## 5. Phase 2: Implementation Strategy

*(This section provides a high-level guide for the implementation phase, which will be detailed further in `tasks.md`)*

### a. Fact Data Structures (`src/models/fact.py`)
-   Implement the `Fact` Pydantic model as defined in `data-model.md`, including `serialize_canonical` and `generate_id` methods.

### b. Ingestion Queue (`src/queue/fact_queue.py`)
-   Define `IFactQueue` as an `abc.ABC`.
-   Implement `MemoryFactQueue` using `asyncio.Queue`, `asyncio.Lock`, and a `set` for duplicate detection as per `research.md`.

### c. Fact Dispatcher (`src/dispatcher/fact_dispatcher.py`)
-   Define `IFactHandler` as an `abc.ABC`.
-   Implement `FactDispatcher` to manage `IFactQueue` consumption, handler registration, and parallel dispatching using `asyncio.gather`.

### d. Handler Stubs (`src/handlers/` and relevant files)
-   Create `FastInferenceHandler` and `DeepReasoningHandler` as simple concrete implementations of `IFactHandler`. These will serve as placeholders for future reasoning logic.

### e. Working Memory (`src/memory/` or `src/graph/`)
-   Implement `MemoryNode` as a Python class or Pydantic model, holding an `item` (Fact/Rule), `activation_level`, and `last_accessed`.
-   Implement `AttentionGraph`, managing a dictionary of `MemoryNode`s and providing `stimulate`, `decay`, `prune`, and `get_active_subgraph` methods.
